# Zigbee Link

Приложение Home Assistant OS для стабильного Ethernet-подключения одного или нескольких LAN Zigbee-координаторов со статическими IP. Создаёт общий `zigbee0` на существующем Ethernet-порту, сохраняя обычное подключение HA.

**Предварительный выпуск 1.2.0.** Добавлено независимое автоматическое восстановление нескольких экземпляров Zigbee2MQTT. Оно выключено по умолчанию и включается после явной привязки каждого приложения к своему координатору. Статус проверок и ограничения указаны в [документации](zigbee_link/DOCS.md).

[Добавить репозиторий в Home Assistant](https://my.home-assistant.io/redirect/supervisor_add_addon_repository/?repository_url=https%3A%2F%2Fgithub.com%2FStepan-fair%2Fzigbee-link)

Либо добавьте `https://github.com/Stepan-fair/zigbee-link` в **Настройки → Приложения → Магазин приложений → Репозитории**. Установите **Zigbee Link**, откройте настройки, затем запустите приложение и проверьте журнал.

По умолчанию HA получает `172.31.254.1/24`. Заранее задайте в прошивках координаторов статические `172.31.254.2`, `172.31.254.3` и далее с маской `255.255.255.0`. Адреса самого роутера не меняются. DHCP для координаторов не используется; приложение не назначает адреса устройствам автоматически.

Один экземпляр приложения обслуживает несколько координаторов. Для каждого координатора нужен отдельный экземпляр Zigbee2MQTT со своими данными и MQTT topic. ZHA штатно поддерживает один координатор.

Все устройства подключаются кабелями к общему Ethernet-сегменту. Подсеть не обязана совпадать с обычной LAN, но не должна пересекаться с действующими сетями HA. Гарантировать свободные адреса в любой чужой сети невозможно. Изоляция портов/гостевая сеть и блокировка дополнительных MAC могут препятствовать связи.

При включённом восстановлении исчезнувший координатор ожидается без ограничения срока. После его возвращения приложение проверяет сеть и зависимости, запускает соответствующий Zigbee2MQTT и проверяет ответы. Пауза обслуживания сохраняется в настройках; ограничения перезапусков и незавершённые команды сохраняются на диске. Один отсутствующий координатор не мешает обслуживать остальные.

Приложение не содержит настроек конкретного дома, не отправляет диагностику во внешние службы, не меняет роутер, DHCP-профиль HA или настройки Zigbee2MQTT. Требуются NET_ADMIN/NET_RAW, host networking и Supervisor API с ролью manager; AppArmor включён. Код разрешает только start/restart явно привязанных приложений, но полномочие manager на уровне платформы шире этой программной проверки.

Исходники доступны в этом репозитории. Для разработки: Python 3.12+, `pytest`, `PyYAML`, `paho-mqtt==2.1.0`. Windows: `python -m pytest tests -q --tb=short -m "not linux"`. Для полного Linux-прогона дополнительно нужны `scapy`, iproute2, ping, iptables, Mosquitto, OpenSSL и root-права для изолированных тестовых namespaces: `sudo python -m pytest tests -q --tb=short`. Окружение контейнерных проверок описано в GitHub Actions. Для упаковки используйте `python tools/package.py --output <новый-пустой-каталог-вне-исходников>`.
