# Zigbee Link

Приложение Home Assistant OS для стабильного Ethernet-подключения одного или нескольких LAN Zigbee-координаторов со статическими IP. Создаёт общий `zigbee0` на существующем Ethernet-порту, сохраняя обычное подключение HA.

**Предварительный выпуск 1.3.0.** Новый русский экран получает сведения об установленных Zigbee2MQTT и MQTT, предлагает привязки координаторов и сохраняет ручные исправления. Для нескольких сетей остаются отдельные разрешения и паузы. Восстановление выключено по умолчанию. Статус проверок и ограничения указаны в [документации](zigbee_link/DOCS.md).

[Добавить репозиторий в Home Assistant](https://my.home-assistant.io/redirect/supervisor_add_addon_repository/?repository_url=https%3A%2F%2Fgithub.com%2FStepan-fair%2Fzigbee-link)

Либо добавьте `https://github.com/Stepan-fair/zigbee-link` в **Настройки → Приложения → Магазин приложений → Репозитории**. Установите **Zigbee Link** и запустите приложение.

Откройте его веб-интерфейс из Home Assistant, выберите **«Перейти к настройке здесь»** и подтвердите показанный перенос. Затем нажмите **«Найти сети»**, добавьте подходящие сети для наблюдения и при необходимости разрешите восстановление в целом и **«Поддерживать сеть включённой»** для каждой нужной сети. Поля, которые не удалось получить автоматически, можно исправить; источник и время получения показаны рядом с ними. После принятия сети её IP не нужно повторно вводить в другой список.

Экран доступен администраторам через штатный Ingress на Supervisor **2026.10.2 или новее**. На старых версиях остаётся прежняя конфигурация; приложение не обновляет Supervisor самостоятельно. Поддерживаются установленные приложения Zigbee2MQTT 2.14.2–2.x и один выбранный MQTT-брокер. Внешние Zigbee2MQTT и несколько разных брокеров одновременно не входят в 1.3.0.

По умолчанию HA получает `172.31.254.1/24`. Заранее задайте в прошивках координаторов статические `172.31.254.2`, `172.31.254.3` и далее с маской `255.255.255.0`. Адреса самого роутера не меняются. DHCP для координаторов не используется; приложение не назначает адреса устройствам автоматически.

Один экземпляр приложения обслуживает несколько координаторов. Для каждого координатора нужен отдельный экземпляр Zigbee2MQTT со своими данными и MQTT topic. ZHA штатно поддерживает один координатор.

Все устройства подключаются кабелями к общему Ethernet-сегменту. Подсеть не обязана совпадать с обычной LAN, но не должна пересекаться с действующими сетями HA. Гарантировать свободные адреса в любой чужой сети невозможно. Изоляция портов/гостевая сеть и блокировка дополнительных MAC могут препятствовать связи.

При включённом восстановлении исчезнувший координатор ожидается без ограничения срока. После его возвращения приложение проверяет сеть и зависимости, запускает соответствующий Zigbee2MQTT и проверяет ответы. Пауза обслуживания сохраняется в настройках; ограничения перезапусков и незавершённые команды сохраняются на диске. Один отсутствующий координатор не мешает обслуживать остальные.

Приложение не содержит настроек конкретного дома, не отправляет диагностику во внешние службы, не меняет роутер, DHCP-профиль HA или настройки Zigbee2MQTT. Требуются NET_ADMIN/NET_RAW, host networking и Supervisor API с ролью manager; AppArmor включён. Код разрешает start/restart явно привязанных приложений и запись только собственного способа настройки при подтверждённом переносе. Полномочие manager на уровне платформы шире этих программных проверок. Для обнаружения serial TCP-порт координатора не открывается.

Исходники доступны в этом репозитории. Для разработки: Python 3.12+, `pytest`, `PyYAML`, `paho-mqtt==2.1.0`, `aiohttp==3.14.5`. Windows: `python -m pytest tests -q --tb=short -m "not linux"` с разрешёнными loopback-соединениями. Для полного Linux-прогона дополнительно нужны `scapy`, iproute2, ping, iptables, Mosquitto, OpenSSL и root-права для изолированных тестовых namespaces: `sudo python -m pytest tests -q --tb=short`. Окружение контейнерных проверок описано в GitHub Actions. Для упаковки используйте `python tools/package.py --output <новый-пустой-каталог-вне-исходников>`. Синтетический экран для браузерной проверки: `python tools/setup_ui_fixture.py --port 18765`; он слушает только loopback и не использует реальные серверы.
